# 리모리 (Remory) — 망각곡선 단어장

**Remory**는 **REMEMBER + MEMORY**에서 따온 이름입니다.

영어 단어부터 자격증 개념까지, 기억하고 싶은 내용을 카드로 만들고 예정된 복습일에 다시 만나는 모바일 중심 학습 앱입니다. **Dreamy Memory Garden**을 콘셉트로, 구름새 몽이와 함께 복습해요.

## 주요 기능

- **카드 만들기** · 질문과 답, 단어와 예문, 빈칸 채우기, 객관식 네 가지 유형을 지원합니다. 카드 상세에서 내용을 수정하면 복습 기록과 다음 복습일이 유지됩니다.
- **일괄 등록** · 스프레드시트에서 복사한 내용을 붙여넣거나 엑셀(.xlsx) 파일을 선택해 카드를 한 번에 등록할 수 있습니다. 카드 유형별로 예시가 포함된 엑셀 양식을 내려받을 수 있고, 파일은 브라우저에서 읽습니다.
- **학습 덱** · 외국어, 개발, 역사, 일반 유형에 따라 아이콘과 기본 색상이 정해집니다. 선택한 색상은 카드 미리보기와 복습 화면에도 적용됩니다. 덱 상세 상단에서 이름·설명·테마를 수정해도 카드와 복습 일정·기록은 유지됩니다. 덱을 삭제하면 포함된 카드와 복습 기록도 함께 삭제되며, 삭제 전에 범위를 안내합니다.
- **카드 검색·필터** · 덱 안에서 질문·답·보기를 검색하고 카드 유형, 지금 복습할 카드, 복습 예정, 자주 틀린 카드로 좁힐 수 있습니다. 자주 틀린 카드는 전체 기간에 ‘다시’를 2회 이상 고른 카드이며, 검색과 필터를 함께 적용할 수 있습니다.
- **간격 복습** · 복습일이 된 카드를 다시 만나고, 기억한 정도를 네 단계로 평가해 다음 복습일을 정합니다.
- **학습 기록** · 월별 캘린더에서 복습한 날짜를 확인하고, 최근 7일의 학습량을 볼 수 있습니다.
- **화면 설정** · 설정의 다크 모드 선택을 브라우저에 저장합니다.

## 실행하기

```bash
npm ci
npm run dev
```

터미널에 표시되는 로컬 주소를 브라우저에서 열면 됩니다. 배포용 파일은 `npm run build`로 생성할 수 있습니다.

## 기술 스택과 구현 범위

React 19, TypeScript, Vite, Lucide, vite-plugin-pwa를 사용합니다. 비회원의 덱, 카드, 복습 기록은 브라우저에 저장하며 로그인한 사용자의 기록은 서버에 저장합니다. 정규 복습일은 최근 카드별 평가와 복습 사이에 지난 시간을 바탕으로 계산합니다. 자유·집중 복습은 학습 기록에 반영합니다.

## 로컬 계정 연동

회원가입, 로그인과 계정별 학습 기록을 테스트하려면 백엔드 폴더에서 MySQL과 Spring Boot를 먼저 실행하세요. Vite가 개발·미리보기의 `/api` 요청을 기본적으로 `http://127.0.0.1:8080`으로 전달합니다. 다른 환경에는 `REMORY_API_TARGET`으로 로컬 전달 주소를 지정할 수 있습니다. 실제 배포에서는 웹과 동일한 HTTPS 도메인에서 `/api`를 Spring Boot로 전달하세요.

로그인하면 이 기기의 비회원 학습 데이터를 계정으로 가져옵니다. 계정 저장을 확인한 뒤 비회원 화면을 초기화하며, 이관에 실패하면 기존 기록을 유지합니다. 새 브라우저나 기기에서 같은 계정으로 로그인하면 서버에 저장된 기록을 불러옵니다. 이메일 로그인과 Google 로그인을 지원하며, 일반 이메일 계정은 메일로 받은 인증코드를 입력해 비밀번호를 재설정할 수 있습니다. 메일 발송에는 백엔드 SMTP 설정이 필요합니다.

## Google 로그인

로그인·회원가입 화면의 Google 버튼을 사용합니다. 처음 인증하면 계정을 만들고, 재방문하면 연결된 계정으로 로그인합니다. 같은 이메일의 기존 리모리 계정은 비밀번호를 확인한 뒤 Google 계정을 연결합니다. Google 로그인도 같은 비회원 기록 이관 과정을 사용합니다.

백엔드의 `GOOGLE_CLIENT_ID`로 OAuth 클라이언트를 설정합니다. 로컬에서는 Google Auth Platform의 승인된 JavaScript 원본에 `http://localhost`와 `http://localhost:5173`을 등록하고 `http://localhost:5173`으로 접속하세요. 배포할 때는 웹의 HTTPS 원본도 등록합니다. 프런트엔드는 서버에서 클라이언트 ID와 일회용 인증 값을 받아 공식 Google Identity Services 버튼을 표시합니다.

## 회원탈퇴

로그인한 사용자는 설정의 **회원탈퇴**에서 비밀번호를 다시 입력해 계정과 학습 기록을 삭제할 수 있습니다. Google로 가입한 사용자는 설정에서 삭제 내용을 확인하고 Google 본인 인증으로 탈퇴합니다. 외부 브라우저의 `/account-deletion/`에서도 이메일 또는 Google 인증을 선택해 계정을 삭제할 수 있습니다.

배포 후 `dist/account-deletion/index.html`을 `/account-deletion/`에서 열 수 있게 하고, 같은 도메인의 `/api`를 백엔드로 전달하세요. Google Play의 데이터 보안 양식에는 배포 도메인의 공개 회원탈퇴 URL을 등록합니다.


## 비밀번호 재설정

로그인 화면의 **비밀번호를 잊었나요?**에서 이메일 입력 → 메일의 6자리 인증코드 입력 → 새 비밀번호 설정을 같은 화면 안에서 진행합니다. 메일에는 화면 주소나 임시 비밀번호를 보내지 않으며, 웹과 앱에서 같은 흐름을 사용할 수 있습니다.

코드는 10분간 유효하고 최대 5회 입력할 수 있습니다. 재전송은 60초 뒤 가능하며, 만료까지 남은 시간과 재전송 가능 시각을 화면에 표시합니다. 코드 확인 후 새 비밀번호 설정은 5분 안에 마쳐야 합니다. 변경하면 모든 기기의 로그인 세션이 해제되고 저장된 학습 기록은 유지됩니다. 미가입 이메일과 소셜 전용 계정에는 코드를 보내지 않습니다.

인증 화면은 네 언어와 저장된 다크 모드를 사용합니다. 요청 식별자와 변경 권한은 컴포넌트 메모리에만 두고 URL이나 브라우저 저장소에 넣지 않습니다. `/password-reset/`에서도 같은 컴포넌트를 사용할 수 있으며 앱 링크 연결은 필요하지 않습니다. 배포 시 `dist/password-reset/index.html`을 해당 경로에서 제공하고 `/api`는 백엔드로 전달하세요.


## 로그인 유지

이메일과 Google 로그인 모두 창이나 앱을 다시 열면 갱신 쿠키로 계정과 저장된 학습 기록을 복원합니다. 접근 토큰은 메모리에만 두고, 갱신 권한은 JavaScript에서 읽을 수 없는 지속 쿠키로 저장합니다. 접근 토큰은 15분마다 갱신합니다. 서버에는 미사용 기간만으로 로그아웃되는 제한을 두지 않고 로그아웃·비밀번호 재설정·탈퇴·보안상 폐기 시 해제합니다. 브라우저의 갱신 쿠키는 400일로 발급하고 갱신할 때마다 연장합니다. 브라우저 보관 정책이나 쿠키·앱 데이터 삭제로 쿠키가 사라지면 다시 로그인해야 합니다.

만료 1분 전에 자동 갱신하고, 앱으로 돌아왔거나 API가 401을 반환한 경우에도 갱신 후 한 번 재시도합니다. 동시에 발생한 요청은 하나의 갱신 결과를 공유하며, Web Locks 지원 환경에서는 탭 간 갱신·로그인·로그아웃도 직렬화합니다. 다른 탭의 로그인·로그아웃을 반영하고 계정 변경 뒤 도착한 이전 계정의 응답은 적용하지 않습니다.

일시적인 통신 오류 때문에 계정을 지우지 않으며 복원 오류에서 다시 연결할 수 있습니다. 비회원으로 계속하기를 선택하면 재연결 후에도 이전 계정으로 임의 복원되지 않도록 로그아웃 처리를 유지합니다. 비회원 기록 이관은 기존처럼 계정 저장 확인 후에만 로컬 기록을 비웁니다.

테스트는 Node.js 22.12 이상에서 `npm test`로 실행합니다. 세션·요청 테스트와 React 학습 상태 테스트에서 재실행 복원, 동시 401 갱신, 갱신 실패, 로그아웃·계정 전환 경합과 비회원 이관을 확인합니다. 실제 메일이나 사용자 계정은 사용하지 않습니다.
